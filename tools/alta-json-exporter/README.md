# Alta JSON exporter

Standalone Chrome/Edge 120+ extension for saving Alta API JSON through ordinary browser tab navigation. Version 0.4.0 optionally embeds public product photos in uploader-ready JSON and splits import downloads into bounded selectable parts. It accepts an owner-issued signed stock-feed link without an admin login, and requests Georgian Alta API responses with `Accept-Language: ka`. The icon opens `panel.html`; the background script only opens or focuses that panel. Collection runs in the open panel, with no background messaging, schedule, automatic import, or catalogue POST.

## Use

1. Unzip into a permanent folder. Open `edge://extensions/` or `chrome://extensions/`, enable Developer mode, select Load unpacked and choose the folder containing `manifest.json`. Open the panel from its IAPI icon. No Node.js, PHP, package installation or IAPI account is required for the file/code workflow. Georgian instructions are in `INSTALL-KA.txt`.
2. Paste the owner's stock-feed link into **B2B სიის წვდომის ბმული** and click **სიის ჩატვირთვა**. IAPI host permission is requested directly by that click; no admin session is needed. Only the exact HTTPS path `/feeds/alta-stock.json` on `iapi.ge` is accepted, with exactly one UUID `version` and one64-hex `signature` parameter. Extra parameters, fragments, credentials, foreign hosts and nonstandard ports are rejected. The link is saved only in this extension's local storage and is not included in product exports or the share ZIP. Treat the link as private read access to supplier stock: its owner can revoke it by issuing a replacement.
   Alternatively, paste exact item codes or select your own B2B JSON feed file. `examples/product-codes.txt` contains public trial codes. `examples/b2b-template.json` contains synthetic placeholders: replace them and the quantities with real B2B data. These modes do not require IAPI access.
3. Leave the limit at3 for a sample; `0` selects every supplied item. Pasted codes select a subset of a loaded feed. Without a feed, pasted codes can still collect raw results.
4. **ფოტოების შენახვა JSON-ში** is checked initially. Start or Resume requests optional access to `imgstore.alta.ge` directly in that click. Allow it to save photos, or uncheck the option for URL-only exports. Keep the panel open and let its own helper tab navigate normally. Every API/feed navigation is paced by at least one second; at most five candidate product IDs are checked. A details barcode must exactly match the B2B item code.
5. Pause or resume from the saved product position. A challenge, unavailable page, invalid JSON, or timeout pauses the current item and preserves earlier results. There is no automatic challenge interaction or retry loop.
6. Download **საწყისი JSON** for the complete original matched details responses, unchanged. For import, click **ნაწილების მომზადება**, choose a part, and click **იმპორტის JSON** once per part. The first import click can also prepare the plan. Every part is a top-level array of at most100 products and at most8MiB of actual UTF-8 JSON, including embedded photos. The selector lists every part and its product range; upload all parts separately. This copy preserves the full response, replaces `product.storageQuantity` with known B2B quantity, including0, empties `availabilityInStores`, and adds top-level `iapiAssets: [{url, base64}]` when photos were requested. Unknown B2B quantity or unusable retail price/name blocks import; raw download remains available. Loading a feed can supply quantities for previously collected pasted codes.

Raw response bodies are stored per product in IndexedDB rather than extension local storage. Photos use a separate IndexedDB object store; schema version2 preserves existing raw rows. Only job progress, exact codes, B2B quantities and the photo option are stored in `chrome.storage.local`. Import planning reads one raw/photo row at a time and retains only product references in its plan; it does not load all photo payloads with `getAll`. Serialization is bounded to the selected part. Raw download remains one complete array of original responses and does not load the photo store. The current job survives panel closure. Starting a new job changes the current panel job without deleting older stored records; download existing partial results first if they are needed.

The raw details row is saved before photo collection. A photo error pauses at that product and leaves its full raw JSON downloadable. Resume checks the existing row and collects missing photos without repeating that product's API request. Enabling photos while resuming an older paused job revisits saved raw rows. A completed older job remains available as originally collected; start a new job to collect it with photos. Unchecking the option before Resume continues with URL-only import. Pause prevents a late photo response from writing assets.

With the photo checkbox checked, preparing or downloading an older completed URL-only job is blocked rather than silently omitting photos. Start a new collection for photos, or uncheck the option to explicitly export that old job with URLs only. Raw download is always unchanged. If another open panel blocks the IndexedDB upgrade, close the other Alta JSON panels and reload the current page; closing another panel alone does not reset the failed connection in this page.

Photo downloads are ordinary extension `fetch` GETs with `credentials: 'omit'`, `redirect: 'error'`, no custom headers and a15-second deadline per photo. Only HTTPS URLs on exact `imgstore.alta.ge/images/` or `alta.ge/images/` raster paths are accepted. Explicit ports, credentials, query strings, fragments, traversal and SVG are rejected. Main `imageUrl` comes first, followed by unique `images`, limited to the first8. Each image is capped at1MiB and each product at2MiB of binary data; stream reading stops at the limit. A200 response must be JPEG, PNG, GIF or WebP, successfully decoded by `createImageBitmap`, no more than12000 pixels per side and40million pixels total.403, redirects, HTML/challenges, decode errors, size failures and timeouts stop the current product without automatic retries. If a public photo is denied, this extension reports the error and does not bypass it.

Signed feeds use schema `iapi.supplier-stock.v1`, supplier `alta`, source `supplier_stocks`, an ISO `synced_at`, matching `count`, and all item/quantity rows including0. Approved error responses never replace a saved feed. Source and snapshot time are retained with the feed and job. Signed stock older than26hours, invalid timestamps and timestamps more than5minutes in the future block collection, resume and import export. Raw product downloads remain available. Load a fresh feed to continue; replacing a feed clears quantities for items absent from it. Generic manually supplied file/code data has no server freshness guarantee. Pre0.3 quantities with unknown provenance require reloading the feed or file before import.

Before each Alta search/details navigation, the reader installs a tab-specific session rule setting `Accept-Language: ka`. The rule matches only the owned helper tab, main-frame requests and the exact two Alta API routes. Rule installation is awaited before the first API request; failure stops collection instead of silently requesting the default language. IAPI navigation removes this extension's own rule. It uses Chrome's documented [session rules and header modification API](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest).

API responses are preserved exactly; the header requests Georgian but cannot translate missing source fields. The browser locale remains unchanged. Start a **new collection** after updating to recollect older English responses: Resume intentionally reuses already saved raw data. Raw downloads always retain original photo URLs; embedded binaries appear only in the import copy when requested.

## Boundaries

Required host permission is limited to `https://alta.ge/*`; `https://iapi.ge/*` is optional and requested only by the signed-feed action, while `https://imgstore.alta.ge/*` is optional and requested only by Start/Resume with photos checked. Denial leaves the corresponding file/code or URL-only workflow available. This uses Chrome's documented [optional permissions flow](https://developer.chrome.com/docs/extensions/reference/api/permissions). Permissions are `scripting`, `storage` and `declarativeNetRequestWithHostAccess` for the scoped API language header. No global `tabs`, `downloads`, cookies, debugger, proxy or web-request permission is requested. It reads rendered API JSON text from its own helper tab and uses normal fetch only for approved public media. It does not call the Alta API with fetch, inspect hidden framework state, export authentication data, solve challenges, or upload products.

The panel uses a browser Web Lock to prevent concurrent collectors across panels. Navigation and script-injection waits are bounded. Results are checkpointed after each product. Downloads use a Blob and anchor, with no download permission.

The share ZIP contains runtime files, icons, Georgian instructions and examples. It excludes tests, the Laravel application, account credentials, saved browser data and the owner's B2B feed. Keep the installed folder in place when updating; replace its files and use Reload on the extensions page to preserve extension identity and stored work.

Run local fixtures from the repository root:

```sh
node --test tools/alta-json-exporter/tests/*.test.mjs
```
